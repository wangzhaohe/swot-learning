runes 魔法符文

魔法符文是用在文件 .svelte and .svelte.js / .svelte.ts 中的，用来控制编译器。

魔法符文是以 $ 开始关键字，像是一个函数的调用。如下：

let message = $state('hello');

特点：

  1. 自动导入，无需手动 import

  2. 魔法符文本身不能赋值给一个变量，也不能被作为参数传递给函数。

  3. 如果用错了，编译器会进行提示。

$state()

https://svelte.dev/docs/svelte/$state

https://svelte.dev/tutorial/svelte/state

创建响应式状态，让 UI 跟着变化。

<script>
	  let count = $state(0);
</script>

<button onclick={() => count++}>
	  clicks: {count}
</button>

Deep state 默认是深度响应式

深度状态：Deep state

$state 会为数组和普通对象创建“深度响应式代理”（deeply reactive state proxy）。

解构会丢失响应性：如果从响应式对象中解构出属性，解构出的变量将只是普通值，不再具有响应性。比如下面代码中的 done 和 text 都不具响应性了。

let { done, text } = todos[0];

// this will not affect the value of `done`
// 下面再赋值，也无法使 done 成了响应式的变量，这点要注意一下
todos[0].done = !todos[0].done;

// 网页中再这样使用就不行了 <p>{done}</p>

$state 用在 class 里的响应式验证

本篇验证 Svelte 5 官方文档 https://svelte.dev/docs/svelte/$state#Classes 中的写法：

class 实例本身不会被 proxy 代理，但可以把 $state 用在 class 字段声明，或构造函数里对属性的首次赋值上。 比如该例子中的 done 和 text 两个属性的定义就是这样的。下面我们进行测试。

环境：Svelte ^5.56.1，vite.config.js 已强制开启 runes: true，Vitest（server + client 两个项目）。

1. 官方示例（后面要验证 $state 的写法）
src/lib/state-class/Todo.svelte.js
/* global $state */

/**
 * 验证 https://svelte.dev/docs/svelte/$state#Classes 中的写法。
 *
 * 官方说明：class 实例本身**不会**被 proxy 代理，但可以分别在
 *  1. class 字段声明处（public / private 都可）
 *  2. 构造函数里对某个属性的**首次**赋值处
 * 使用 `$state`，从而让单个属性具备响应式。
 *
 * 注意：文件名必须是 `*.svelte.js`，模块里的 runes 才会被编译。
 */
export class Todo {
    /** 字段声明处使用 $state */
    done = $state(false);

    /**
     * @param {string} text
     */
    constructor(text) {
        /** 构造函数中对该属性的首次赋值处使用 $state */
        this.text = $state(text);
    }

    /** 把两个响应式字段一起重置 */
    reset() {
        this.text = '';
        this.done = false;
    }
}

监听器定义
src/lib/state-class/tracker.svelte.js
/**
 * https://share.gemini.google/4Do68CR3eWIS gemini 说明该代码
 * `$effect` 在 node/SSR 编译产物里是空实现，所以响应式断言必须跑在 client（浏览器）项目。`tracker.svelte.js` 在 `$effect.root` 里订阅一个 getter
 * runes 只能在 `.svelte` / `.svelte.js` 文件里使用，所以这个辅助函数单独放在 `.svelte.js` 中。
 * tracker.svelte.js = 一个可挂在任意 getter 上的响应式监听器 + 计数器。
 * runs 计数不动,说明被观察的东西没有响应式;
 * runs 计数随修改增加,说明它是货真价实的 $state 响应式属性。
 * 它是你验证 "class 里 $state 用对没有" 的测试利器。
 */

/* global $effect */
import { flushSync } from 'svelte';

/** @param {() => unknown} getter 读取待观察属性的函数 */
export function createTracker(getter) {
    /** @type {unknown} */
    let value = undefined; // 保存最近一次读到的值
    let runs = 0;          // effect 被执行的次数

    // 1. 开启一个不受组件生命周期限制的全局副作用监听
    const destroy = $effect.root(() => {
        $effect(() => {
            value = getter();  // 告诉 $effect 要观察的值，比如 done/text
            runs += 1;         // 只要值变了， effect 就会重跑，次数 +1
        });
    });

    // 2. 强制立即同步执行一次，确保初始状态下的 value 和 runs 有值 (runs 变成 1)
    flushSync();

    return {
        /** effect 最近一次读到的值 */
        get value() {
            return value;
        },
        /** effect 被执行了多少次 */
        get runs() {
            return runs;
        },
        /**
         * 修改状态并同步 flush，确保 effect 已经重跑
         * @param {() => void} mutate
         */
        run(mutate) {
            flushSync(mutate);
        },
        destroy
    };
}

// 原因是 Svelte 在 node/SSR 编译产物中 $effect 不会执行，只有客户端才能真正验证响应式。
// 同理，Todo.svelte.js / tracker.svelte.js 必须带 .svelte.js 后缀，runes 才会被编译。

describe('Todo：把 $state 用在 class 里', () => {
    it('字段声明处的 $state(false) 初始值正确', () => {
        const todo = new Todo('learn svelte');
        expect(todo.done).toBe(false);
    });
    it('构造函数首次赋值处的 $state(text) 初始值正确', () => {
        const todo = new Todo('learn svelte');
        expect(todo.text).toBe('learn svelte');
    });
    it('修改 done（字段声明式 $state）会触发响应式更新', () => {
        const todo = new Todo('learn svelte');
        const tracker = createTracker(
            () => todo.done
        );

        expect(tracker.value).toBe(false);
        expect(tracker.runs).toBe(1);

        tracker.run(() => {
            todo.done = true;
        });

        expect(todo.done).toBe(true);
        expect(tracker.value).toBe(true);
        expect(tracker.runs).toBe(2);
    });
    it('修改 text（构造函数式 $state）会触发响应式更新', () => {
        const todo = new Todo('learn svelte');
        const tracker = createTracker(
            () => todo.text
        );

        expect(tracker.value).toBe('learn svelte');

        tracker.run(() => {
            todo.text = 'learn runes';
        });

        expect(todo.text).toBe('learn runes');
        expect(tracker.value).toBe('learn runes');
        expect(tracker.runs).toBe(2);
    });
    it('reset() 同时重置两个字段，并各自触发更新', () => {
        const todo = new Todo('learn svelte');
        const doneTracker = createTracker(() => todo.done);
        const textTracker = createTracker(() => todo.text);

        doneTracker.run(() => {
            todo.done = true;
            todo.text = 'changed';
        });

        expect(doneTracker.value).toBe(true);
        expect(textTracker.value).toBe('changed');
        expect(doneTracker.runs).toBe(2);
        expect(textTracker.runs).toBe(2);

        textTracker.run(
            () => todo.reset()
        );

        expect(todo.text).toBe('');
        expect(todo.done).toBe(false);
        expect(textTracker.value).toBe('');
        expect(doneTracker.value).toBe(false);
        expect(textTracker.runs).toBe(3);
        expect(doneTracker.runs).toBe(3);
    });
    it('实例本身没有被 proxy：后加的普通属性不具备响应式', () => {
        /**
         * note 是后加的普通属性，就是为了测试它不具备响应式
         * @type {Todo & { note?: string }}
         */
        const todo = new Todo('learn svelte');
        const tracker = createTracker(
            () => todo.note
        );

        expect(tracker.runs).toBe(1);

        tracker.run(() => {
            todo.note = 'not reactive';  // 此处可以随便给字符串
        });

        // 值确实写进去了，但 effect 没有重跑 —— 说明实例不是 proxy 的响应式
        expect(todo.note).toBe('not reactive');
        expect(tracker.runs).toBe(1);  // 如果 note 是响应式，就会触发 $effect
    });

/* global $state */

/**
 * private 字段（`#done = $state(false)`）示例
 * 文档里说 `$state` 可以用在 class 字段上，「无论是 public 还是 private」。
 * 这里验证 private（`#` 私有字段）的写法，并通过 getter / setter 暴露。
 */
export class PrivateTodo {
    #done = $state(false);  // 私有属性

    /** @param {string} text */
    constructor(text) {
        this.text = $state(text);
    }

    get done() { return this.#done; }

    /** @param {boolean} value */
    set done(value) { this.#done = value; }

    reset() {
        this.text = '';
        this.done = false;
    }
}

/**
 * 这个用例跑在 server（node）项目里：只做编译期校验，不需要 $effect，也就不需要浏览器。
 * 编译期合法性与报错校验（4 个）
 */

import { compileModule } from 'svelte/compiler';
import { describe, expect, it } from 'vitest';

/**
 * 按 client 模式编译一段源码，返回报错信息；没有报错则返回 null。
 * @param {string} source
 */
function compileError(source) {
    try {
        compileModule(source, {
            generate: 'client',
            filename: 'case.svelte.js'
        });
        return null;
    } catch (error) {
        return /** @type {Error} */ (error).message;
    }
}

describe('$state 在 class 里的合法 / 非法位置', () => {
    /**
     * 两种写法：作为属性和构造方法的首次赋值都正确
     * 注意 $state 是作为字符串存在的
     */
    it('文档里的两种写法都能正常编译', () => {
        const message = compileError(`
            export class Todo {
                done = $state(false);
                constructor(text) {
                    this.text = $state(text);
                }
            }
        `);
        expect(message).toBeNull();
    });
    // 注意 $state 是作为字符串存在的
    it('private 私有字段也能正常编译', () => {
        const message = compileError(`
            export class Todo {
                #done = $state(false);
            }
        `);
        expect(message).toBeNull();
    });
    // 注意 $state 是作为字符串存在的
    it('构造函数里「非首次」赋值会编译报错', () => {
        const message = compileError(`
            export class Todo {
                constructor(text) {
                    this.text = text;
                    this.text = $state(text);  // 这不是首次赋值
                }
            }
        `);
        expect(message).toContain(
            'Cannot assign to a state field before its declaration'
        );
    });
    // 注意 $state 是作为字符串存在的
    it('在普通方法里用 $state 赋值会编译报错', () => {
        const message = compileError(`
            export class Todo {
                addNote() {
                    this.note = $state('x'); // addNote 是一个普通的方法，不能用 $state
                }
            }
        `);
        // 只能在类的构造器中使用 $state
        expect(message).toContain(
            'the first assignment to a class field at the top level of the constructor'
        );
    });

    /**
     * 只有三种情况可以使用 $state:
     * `$state(...)` can only be used as a variable declaration initializer, a class field declaration, or the first assignment to a class field at the top level of the constructor.
     */
});

<script>
import { Todo } from '$lib/state-class/Todo.svelte.js';

/** class 实例组成的数组：数组本身被 proxy，实例本身不会 */
let todos = $state([
    new Todo('读 Svelte 文档'),
    new Todo('写验证代码')
]);

// 用一句话理解：doneCount 是一个"会自动重新计算的数字"，只要跟它相关的数据一变，Svelte 就会自动重算，然后模板里用到它的地方自动更新。
const doneCount = $derived(
    todos.filter((todo) => todo.done).length
);  // 计算 todos 已完成个数

let draft = $state('');  // 定义新增待办响应式变量

/** @param {SubmitEvent} event */
function addTodo(event) {
    /* 不阻止浏览器的默认行为会发生什么
        浏览器的默认动作是：把表单字段序列化，然后导航到 action 指定的 URL——这里没有 action，就导航到当前页面地址（/state-class?）。
        结果是一次整页刷新，后果是：
            todos、draft 这些 $state 全部被重置，刚加的待办没了；
            地址栏会多出一个 ?；
            页面会闪一下（重新走一次 SSR/ hydration
    */
    event.preventDefault();

    const text = draft.trim();
    if (text === '')  // 没有输入内容则退出函数
        return;

    todos.push(new Todo(text));
    draft = '';
}
</script>

$effect

https://svelte.dev/docs/svelte/$effect

Effects are functions that run when state updates, and can be used for things like calling third-party libraries, drawing on <canvas> elements, or making network requests. They only run in the browser, not during server-side rendering. 写在 $effect 中可以被监测到的响应式变量有更新时，$effect函数中的代码就会运行。可以应用到调用第三方库、画画、做网络访问请求。 $effect 函数只会运行在浏览器中，不会运行在 SSR 服务端。

Generally speaking, you should not update state inside effects, as it will make code more convoluted and will often lead to never-ending update cycles. If you find yourself doing so, see when not to use $effect to learn about alternative approaches. 通常来讲，在 $effect 中不要去更新被它监测的变量，因为会特别复杂，也会导致死循环。一旦你这样做了，就去看看 https://svelte.dev/docs/svelte/$effect#When-not-to-use-$effect

举例如下：$effect 监测了 color and size，更改 size or color，则会执行 $effect 函数中的语句

<script>
    let size = $state(50);
    let color = $state('#ff3e00');

    let canvas;

    $effect(() => {
        const context = canvas.getContext('2d');
        context.clearRect(0, 0, canvas.width, canvas.height);

        // this will re-run whenever `color` or `size` change
        context.fillStyle = color;  // 监测 color
        context.fillRect(0, 0, size, size);  // 监测 size
    });
</script>

<canvas bind:this={canvas} width="100" height="100"></canvas>

<div>
    <label>
        大小:
        <input type="range" min="10" max="100" bind:value={size} />
        {size}
    </label>
</div>

<div>
    <label>
        颜色:
        <input type="color" bind:value={color} />
    </label>
</div>

Understanding lifecycle

Your effects run after the component has been mounted to the DOM, and in a microtask after state changes. Re-runs are batched (i.e. changing color and size in the same moment won’t cause two separate runs), and happen after any DOM updates have been applied.

$effect 函数的执行在组件挂载之后，而且是在监测的响应式变量更新以后在微任务中执行。比如同时更改了 color and size，$effect 中的代码是在 DOM 更新后批量执行的，不会分开执行。

You can use $effect anywhere, not just at the top level of a component, as long as it is called while a parent effect is running.

$effect 不单单是只能在组件的顶层去使用，它在一个已有的 $effect 内部调用也是可以的，但是不能独立在函数或条件分支中直接调用。

不能用的例子
<script>
	let count = $state(0);

	function setupEffect() {
		// ❌ 错误！没有父级 effect 在运行
		$effect(() => {
			console.log(count);
		});
	}

	setupEffect(); // 这里调用会报错
</script>

了解 teardown function 函数，在清理副作用时很有用。

Understanding dependencies

$effect automatically picks up any reactive values ($state, $derived, $props) that are synchronously read inside its function body (including indirectly, via function calls) and registers them as dependencies. When those dependencies change, the $effect schedules a re-run.

$effect 监测的 同步 运行的响应式变量们，在变化时，$effect 函数中的代码会重新运行。

If $state and $derived are used directly inside the $effect (for example, during creation of a reactive class), those values will not be treated as dependencies.

直接在 $effect 中使用 $state and $derived 定义的变量，就不能被当作 $effect 的依赖。

Values that are read asynchronously — after an await or inside a setTimeout, for example — will not be tracked. Here, the canvas will be repainted when color changes, but not when size changes (demo):

异步读取的响应式变量，也不会成为依赖。如下例 color 是依赖，size 还是依赖。

$effect(() => {
    const context = canvas.getContext('2d');
    context.clearRect(0, 0, canvas.width, canvas.height);

    // this will re-run whenever `color` changes...
    context.fillStyle = color;

    setTimeout(() => {
        // ...but not when `size` changes
        context.fillRect(0, 0, size, size);
    }, 0);
});

An effect only reruns when the object it reads changes, not when a property inside it changes. (If you want to observe changes inside an object at dev time, you can use $inspect.)

<script>
    let state = $state({ value: 0 });
    let derived = $derived({ value: state.value * 2 });

    // this will run once, because `state` is never reassigned (only mutated)
    $effect(() => {
        state;
    });

    // this will run whenever `state.value` changes...
    $effect(() => {
        state.value;
    });

    // ...and so will this, because `derived` is a new object each time
    $effect(() => {
        derived;
    });
</script>

<button onclick={() => (state.value += 1)}>
    {state.value}
</button>

<p>{state.value} doubled is {derived.value}</p>

An effect only depends on the values that it read the last time it ran. This has interesting implications for effects that have conditional code.

注意 $effect 能够监测响应式变量并重新运行的条件是：$effect 上次运行时读取了哪些响应式变量。

For instance, if condition is true in the code snippet below, the code inside the if block will run and color will be evaluated. This means that changes to either condition or color will cause the effect to re-run.

例如，上一次执行 $effect 函数时，condition 是 true 时，condition 和 color 都会被监测到。

Conversely, if condition is false, color will not be evaluated, and the effect will only re-run again when condition changes.

相反地，如果 condition 是 false，color 就不能被监测到，只有当 condition 变化时，$effect 才会重新运行。

import confetti from 'canvas-confetti';

let condition = $state(true);
let color = $state('#ff3e00');

$effect(() => {
    if (condition) {
        confetti({ colors: [color] });
    } else {
        confetti();
    }
});

$props.id

文档：https://svelte.dev/docs/svelte/$props#$props.id()

作用: 生成一个在当前组件实例内唯一且稳定的 id，主要用于表单元素的可访问性（label 和 input 的 for/id 配对）。

基本用法

<script>
  const uid = $props.id();
</script>

<label for="{uid}-firstname">First Name:</label>
<input id="{uid}-firstname" type="text" />

<label for="{uid}-lastname">Last Name:</label>
<input id="{uid}-lastname" type="text" />

要点：调用一次，存到变量，用后缀拼出多个 id。

为什么需要它

核心价值：同一组件被渲染多次时，避免 id 冲突。

<NameForm />
<NameForm />

  • 写死 id="firstname" → 页面上出现重复 id，<label> 全指向第一个 input，可访问性坏掉

  • 用 $props.id() → 每个实例拿到不同 id（如 svelte-1a2b3c、svelte-4d5e6f），互不干扰

关键结论

  1. 组件会被多次实例化（可复用组件、表单等），有意义，刚需

  2. 组件在整个应用中只会渲染一次，写死字符串也行

补充

  • SSR 场景下，服务端和客户端需要生成一致的 id 才能 hydration 成功，$props.id() 内部会处理。

  • 不能用 Math.random() 之类的代替，会破坏 hydration。

一句话记忆: 它不是为了"在一个组件里区分多个 id"，而是为了"让同一组件的不同实例之间 id 不冲突"。

export { default as thing } from './Thing.svelte';

2. 页面用「命名空间导入」拿到这个对象：

<script>
	// 命名空间导入：my 是一个对象，my.stuff / my.thing 是其中的组件
	import * as my from './my.js';
</script>

3. 模板里用点号访问：

	<my.stuff />
	<my.thing />
核心原理

Svelte 判定一个标签是「组件」还是「HTML 元素」只看标签名：

  • 首字母小写且不含点号（如 <div>）→ 普通 HTML 元素；

  • 首字母大写（如 <Widget>）或含点号（如 <my.stuff>）→ 组件。

所以 <my.stuff> 里的 my 必须是作用域内一个真实存在的对象，.stuff 是它的一个成员、且该成员是一个组件。import * as my from './my.js' 正好返回这样“命名空间对象”，点号前面的 my 就是命名空间，后面的 stuff 就是组件名——和 ES 模块的命名空间语义完全一致。

校验结果

运行 svelte-check 结果：新增的 4 个文件零错误零警告，<my.stuff /> / <my.thing /> 这种点号写法编译通过。

备注：若你更想要单文件自包含的写法，也可以不建 my.js，直接在页面里 import Stuff from './Stuff.svelte'; const my = { stuff: Stuff };，效果一样；但“命名空间”这一概念用 import * as my 表达最贴切，所以我选了当前方案。

在 svelte5 中 passive 属性默认为 true

When using ontouchstart and ontouchmove event attributes, the handlers are passive for better performance. This greatly improves responsiveness by allowing the browser to scroll the document immediately, rather than waiting to see if the event handler calls event.preventDefault().

这里的 passive 模式，核心就一句话：

告诉浏览器：这个事件处理函数不会调用 event.preventDefault()，所以浏览器不用等你的 JS 执行完，就可以立即执行默认行为，比如滚动页面。

1. 先看普通模式

假设你监听触摸移动：

element.addEventListener('touchmove', handleMove);

用户手指移动时，浏览器会遇到一个问题：

「这个 handleMove 函数里面，会不会调用 event.preventDefault() 阻止滚动？」

所以浏览器可能需要：

用户手指移动
    ↓
触发 touchmove
    ↓
先等 JS 的 handleMove 执行
    ↓
看看有没有 preventDefault()
    ↓
确定不会阻止滚动
    ↓
浏览器开始滚动

如果 JS 比较慢，就可能感觉到滚动不跟手。

2. passive 模式解决这个问题

如果告诉浏览器：

element.addEventListener('touchmove', handleMove, {
    passive: true
});

意思就是：

这个 handler 是 passive 的，我保证不会阻止默认行为。

于是浏览器可以：

用户手指移动
    ↓
浏览器：既然你保证不会 preventDefault()
    ↓
立即滚动
    ↓
同时处理 touchmove 的 JS

这样滚动响应会更快。

3. preventDefault() 会发生什么？

例如：

function handleMove(event) {
    event.preventDefault();
}

正常情况下：

touchmove
   ↓
preventDefault()
   ↓
阻止浏览器默认滚动

这对于一些场景是有用的，比如你自己实现一个拖拽、滑动区域，不希望页面跟着滚动。

但是如果事件是：

{ passive: true }

那么你就不能依靠 preventDefault() 阻止默认行为。

也就是说：

function handleMove(event) {
    event.preventDefault(); // passive 下不能用它阻止默认行为
}
4. 为什么 Svelte 对 ontouchstart / ontouchmove 特别处理？

Svelte：

<div ontouchmove={handleMove}>

这里 Svelte 会以 passive listener 的方式处理。即 { passive: true }

结果就是：

touchmove
    ↓
通常与页面滚动密切相关
    ↓
浏览器希望尽快开始滚动
    ↓
passive 可以避免等待 JS 判断
    ↓
滚动更加流畅

所以官方说：

This greatly improves responsiveness

就是提高触摸滚动的响应速度。

5. 一个非常重要的限制

因此，如果你的代码需要：

event.preventDefault()

来阻止触摸默认行为，那么就不能简单依赖：

ontouchmove={handler}

因为 Svelte 这里的 listener 是 passive: true 的。

你可以把 passive 理解成一个承诺：

passive: true

我向浏览器承诺：
“这个事件处理函数不会调用 preventDefault()。”

浏览器因此可以更积极地进行默认行为。

inside an action 解释

这里的 inside an action 指的是：

在 Svelte 的 action（动作函数）里面使用 on 来手动注册事件监听器。

它不是说 on 只能在 action 里面用，而是官方这里举了一个常见场景。

1. 什么是 Svelte action？

Svelte 的 action 是一个函数，可以把某种行为附加到 DOM 元素上。

例如：

<script>
    function clickOutside(node) {
        // 对 node 做一些处理

        return {
            destroy() {
                // 清理
            }
        };
    }
</script>

<div use:clickOutside>
    ...
</div>

这里：

<div use:clickOutside>

就是把 clickOutside 这个 action 应用到 <div>。

可以粗略理解成：

给这个 DOM 元素安装一套自定义行为。

2. 为什么 action 能解决 passive 的问题？

前面我们说：

<div ontouchmove={handleMove}>

Svelte 会使用 passive listener。

所以你不能依靠：

event.preventDefault();

阻止默认行为。

但是某些极少数情况下，你确实需要：

event.preventDefault();

那么可以在 action 中自己调用 DOM API：

<script>
    function myAction(node) {
        function handleMove(event) {
            event.preventDefault();
        }

        node.addEventListener('touchmove', handleMove, {
            passive: false
        });

        return {
            destroy() {
                node.removeEventListener('touchmove', handleMove);
            }
        };
    }
</script>

<div use:myAction>
    ...
</div>

关键就在这里：

node.addEventListener('touchmove', handleMove, {
    passive: false
});

明确告诉浏览器：

passive: false

也就是：

这个 handler 可能调用 preventDefault()，请不要假定它不会。

于是：

function handleMove(event) {
    event.preventDefault();
}

就可以阻止默认行为。

3. 所以官方这句话可以这样理解

原文：

In the very rare cases that you need to prevent these event defaults, you should use on instead (for example inside an action).

这里的逻辑是：

普通情况
    ↓
ontouchmove={handler}
    ↓
Svelte 使用 passive
    ↓
性能更好

极少数情况：

需要 event.preventDefault()
    ↓
不能使用 passive listener
    ↓
使用 on / action
    ↓
自己控制 addEventListener 的配置
    ↓
passive: false

event gotchas

To reduce memory footprint and increase performance, Svelte uses a technique called event delegation. This means that for certain events — see the list below — a single event listener at the application root takes responsibility for running any handlers on the event’s path.

There are a few gotchas to be aware of:

  • when you manually dispatch an event with a delegated listener, make sure to set the { bubbles: true } option or it won’t reach the application root

  • when using addEventListener directly, avoid calling stopPropagation or the event won’t reach the application root and handlers won’t be invoked. Similarly, handlers added manually inside the application root will run before handlers added declaratively deeper in the DOM (with e.g. onclick={…​}), in both capturing and bubbling phases. For these reasons it’s better to use the on function imported from svelte/events rather than addEventListener, as it will ensure that order is preserved and stopPropagation is handled correctly.
