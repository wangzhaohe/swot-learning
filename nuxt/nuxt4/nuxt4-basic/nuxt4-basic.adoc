=== 8.4 有参数路由
有动态参数的路由，如: `/example1/1234`，其中 1234 为动态变化的参数

[upperalpha]
. 创建文件: `touch example1/[id].vue`，其中 id 为动态变化的参数
+
[source,xml]
----
<template>
<div>
    example id: {{ $route.params.id }}
</div>
</template>
----

. 在 <srcipt> 中使用:
+
[source,javascript,]
----
<script setup>
const route = useRoute()
console.log("route.params.id:", route.params.id)  // 在js中捕获参数
</script>
----


关于路由的引入使用，nuxt3/4 和 vue3 是一样的
====
. 下面两个实例只能用在 <template> 中
* $route  当前页的路由实例
* $router 全局路由实例

. 如果想要用在 <script> 中，需要这样引入
* [gray line-through]*import { useRoute, useRouter } from 'vue-router'* 不用写这行
* const route = useRoute()
* const router = useRouter()

. 当前路由实例两种路由参数的获取：
* useRoute().params / $route.params -> url 路径中的参数
* useRoute().query  / $route.query  -> ? 后的参数
====

参考链接：

. https://nuxt.com/docs/getting-started/routing#route-parameters

. https://nuxt.com/docs/api/composables/use-route

. https://nuxt.com/docs/api/composables/use-router

=== 8.5 路由跳转 Nuxt-link
https://nuxt.com/docs/getting-started/routing#navigation

在 template 中的路由跳转语法：

    <NuxtLink to="路由">链接描述</NuxtLink>

.app/pages/nuxtlink.vue
[source,xml]
----
<template lang="pug">
header
    nav
        ul
            li
                NuxtLink(to="/roles") roles
            li
                NuxtLink(to="/roles/admin") admin
            li
                NuxtLink(to="/roles/normal") normal
</template>
----

[NOTE]
====
* 不要使用 <a> 标签，因为会使整个页面重新渲染，属于服务端渲染。
* Nuxtlink 不会刷新整个页面，属于客户端渲染
====

== 11. 静态目录 assets & public
https://nuxt.com/docs/getting-started/assets

assets: 一般用该目录来存放在 #构建阶段# 需要使用的静态文件，还会做一些特殊处理，比如压缩 js 文件。

引用 assets 文件的方式：

    <img src="~/assets/1.jpeg" alt="pinia" />


***
public: 该目录下的内容不会被作压缩等处理，目录下内容相当于在服务器中的静态资源。

* public 下的文件直接被从根目录访问
. 浏览器访问：http://localhost:3000/2.jpeg
. 网页代码访问：<img src="/2.jpeg" alt="" />


TIP: 实际上任何目录都可以，如何更改参下面节点说明。



****
media: 在实际开发中经常需要网站管理员上传一些资源，比如商品的图片等。一般会创建 media 目录，用户将资源上传。
通常在服务器端进行处理，比如使用 nginx web 服务器提供静态资源服务。
但是现代静态资源的部署，通常会使用 OSS 文件服务器进行托管。
****

=== rename assets directory -> 特殊需求才会改
To rename the assets directory in Nuxt 4, you need to update the appropriate
configuration file: #nuxt.config.ts#. Specifically, you need to update the
#dir.assets# property to reflect the new directory name.

.nuxt.config.ts
[source,typescript,linenums]
----
export default defineNuxtConfig({
  dir: {
    assets: 'new-assets-directory-name'
  }

=== auth-middleware.global.ts -- BUG: 如果登录不成功会在地址栏中追加多个redirect
[source,javascript]
----
// 路由全局中间件
export default defineNuxtRouteMiddleware((to, from) => {
    // 用 storeToRefs 解构出响应式变量
    const { authenticated, token } = storeToRefs(useAuthStore())

    // 通过有无 token 来判断是否登录
    if (token.value) {
        authenticated.value = true
    }

    // 有 token，但目标是登录页面，则跳转到主页
    if (token.value && to?.name === 'login') {
        abortNavigation()
        return navigateTo('/')
    }

    // 无 token，但目标不是登录页面，则跳转到登录页面
    if (!token.value && to?.name !== 'login') {
        abortNavigation()
        // 存疑：
        // 此处应该判断是否有 redirect
        // 有则不加，没有则加 redirect
        return navigateTo({
            name: 'login',
            query: { redirect: to.fullPath }  // 登录后的重定向url <1>
        })
    }
})
----

* 这里暗含了一个逻辑：即已登录成功，访问路由不是 login，则直接通行。
所以 nuxt3 不用 next() 挺香，可以不用处理这样的逻辑。

* 还有一个逻辑，即无 token，目标是登录页面，则直接放行。

<1> Bug: 如果登录不成功可能会在地址栏中追加多个 redirect
