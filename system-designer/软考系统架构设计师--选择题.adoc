B. 知识性、生成性与互动性 +

== 计算机基础


=== 分页内存管理
分页内存管理的核心是将虚拟内存空间和物理内存空间皆划分为大小相同的页面，并以页面作为内存空间的最小分配单位。下图给出了内存管理单元的虚拟地址到物理地址的翻译过程，假设页面大小为4KB，那么CPU发出虚拟地址0010000000000100后，其访问的物理地址是（A）。

image::static/分页内存管理.png[分页内存管理,600]

    A 0110000000000100
    B 0100000000000100
    C 1100000000000000
    D 1100000000000010

==== 答案解析
页面大小为 4KB = stem:[2^{12}]B，所以页内偏移占低 12 位。

虚拟地址：

[stem]
++++
0010\ 0000\ 0000\ 0100
++++

* 虚拟页号 = 高 4 位：stem:[0010_2=2]
* 页内偏移 = 低 12 位：stem:[000000000100_2=4]

查页表，页号 2 对应的物理页框号为：

[stem]
++++
110_2=6
++++

物理地址 = 物理页框号拼接页内偏移：

[stem]
++++
110\ 000000000100_2 = 110000000000100_2
++++

即十六进制：

[stem]
++++
0x6004
++++

因此，访问的物理地址是 *0x6004*（或写成二进制 *0110 0000 0000 0100*）。

==== 追加问题
追问：图片中页表最后一列单个数字列表示什么？

图片中页表最后一列的单个数字（0 或 1）表示的是**存在位（Present Bit）**，也叫**有效位（Valid Bit）**。

它的含义是：

* *1*：表示该页面当前*已经调入物理内存*，页表中对应的物理页框号是有效的，可以正常进行地址转换。
* *0*：表示该页面当前*不在物理内存中*（可能还在磁盘上，或者尚未分配），此时如果访问该页面，会触发*缺页中断（Page Fault）*，由操作系统负责将页面从外存调入内存。

结合图片来看：

* 页号 0、1、2、5、9 对应的存在位为 1，说明这些页面在内存中；
* 页号 3、4、6、7、8 对应的存在位为 0，说明这些页面不在内存中。

题目中访问的虚拟页号是 *2*，查表发现页号 2 的存在位为 *1*，物理页框号为 *110*（即 6），因此可以顺利完成地址转换，得到物理地址 0x6004。如果访问的是页号 3，则会因为存在位为 0 而触发缺页中断。

== 数据库


=== 数据库事务
在数据库系统中，“事务”是访问数据库并可能更新各种数据项的一个程序执行单元。为了保证数据完整性，要求数据库系统维护事务的原子性、一致性、隔离性和持久性。针对事务的这 4 种特性，考虑以下的架构设计场景：

假设在某一个时刻只有一个活动的事务，为了保证事务的原子性，对于要执行写操作的数据项，数据库系统在磁盘上维护数据库的一个副本，所有的写操作都在数据库副本上执行，而保持原始数据库不变，如果在任一时刻操作不得不中止，系统仅需要删除副本，原数据库没有受到任何影响。这种设计策略称为（1）。

事务的一致性要求在没有其他事务并发执行的情况下，事务的执行应该保证数据库的一致性。数据库系统通常采用（2）机制保证单个事务的一致性。

事务的隔离性保证操作并发执行后的系统状态与这些操作以某种次序顺序执行（即可串行化执行）后的状态是等价的。两阶段锁协议是实现隔离性的常见方案，该协议（3）。

持久性保证一旦事务完成，该事务对数据库所做的所有更新都是永久的，如果事务完成后系统出现故障，则需要通过恢复机制保证事务的持久性。
假设在日志中记录所有对数据库的修改操作，将一个事务的所有写操作延迟到事务提交后才执行，则在日志中（4），当系统发生故障时，如果某个事务已经开始，但没有提交，则该事务应该（5）。

(1) A 主动冗余
    #B 影子拷贝#
    C 热备份
    D 多版本编程

(2) A 逻辑正确性检查
    B 物理正确性检查
    #C 完整性约束检查#
    D 唯一性检查

(3) #A 能够保证事务的可串行化执行，可能发生死锁#
    B 不能保证事务的可串行化执行，不会发生死锁
    C 不能保证事务的可串行化执行，可能发生死锁
    D 能够保证事务的可串行化执行，不会发生死锁

(4) A 无需记录“事务开始执行”这一事件 
    B 无需记录“事务已经提交”这一事件
    C 无需记录数据项被事务修改后的新值
    #D 无需记录数据项被事务修改前的原始值#

(5) A 抛出异常后退出
    B 撤销
    #C 什么都不做#
    D 重做

==== 答案解析
本题主要考查数据库系统架构设计知识

在数据库系统中，“事务”是访问并可能更新各种数据项的一个程序执行单元。为了保证数据完整性，要求数据库系统维护事务的原子性、一致性、隔离性和持久性。

题干中的第 1 个架构设计场景描述了数据库设计中为了实现原子性和持久性的最为简单的策略：“#影子拷贝#”。
该策略假设在某一个时刻只有一个活动的事务，首先对数据库做副本（称为影子副本），并在磁盘上维护一个 dp_pointer 指针，指向数据库的当前副本。
对于要执行写操作的数据项，数据库系统在磁盘上维护数据库的一个副本，所有的写操作都在数据库副本上执行，而保持原始数据库不变，如果在任一时刻操作不得不中止，系统仅需要删除新副本，原数据库副本没有受到任何影响。

题干中的第 2 个架构设计场景主要考查考生对事务一致性实现机制的理解。事务的一致性要求在没有其他事务并发执行的情况下，事务的执行应该保证数据库的一致性。
数据库系统通常采用 #完整性约束检查# 机制保证单个事务的一致性。

题干中的第 3 个架构设计场景主要考查数据库的锁协议。两阶段锁协议是实现事务隔离性的常见方案，该协议通过定义锁的增长和收缩两个阶段约束事务的加锁和解锁过程，能够保证事务的串行化执行，但由于事务不能一次得到所有需要的锁，因此该协议有可能会导致死锁。

题干中的第 4 个架构设计场景主要考查数据库的恢复机制，主要描述了基于日志的延迟修改技术（deferred-modification technique）的设计与恢复过程。
该技术通过在日志中记录所有对数据库的修改操作，将一个事务的所有写操作延迟到事务提交后才执行，日志中需要记录“事务开始”和“事务提交”时间，还需要记录数据项被事务修改后的新值， #无需记录数据项被事务修改前的原始值#。
当系统发生故障时，如果某个事务已经开始，但没有提交，则该事务对数据项的修改尚未体现在数据库中， #因此无需做任何恢复动作#。

== 软件工程 


=== 软件需求分析
某软件公司承担了某金融公司财务管理系统的建设。
在需求分析阶段，公司分析人员整理出一些相关的系统需求，其中“登陆用户的密码，30天需要修改一次，而且不能使用最近 5 次的密码，以提高系统的安全性”属于 （1） ， +
“要求采用国有自主知识产权的数据库”属于（2）， +
“在凭证录入时对往来款项进行详细的信息录入”属于（3）， +
“用户在凭证录入界面录入信息后，点击保存按钮后，客户认为一般能在 3 秒钟内保存到数据库中” 属于 (4) 。

(1)
A 业务需求
B 功能需求
C 设计约束
#D 非功能需求#

(2)
A 功能需求
B 业务需求
#C 设计约束#
D 非功能需求

(3)
#A 用户需求#
B 功能需求
C 业务需求
D 性能需求

(4)
A 业务需求
#B 期望需求#
C 常规需求
D 意外需求

---

本题主要考查考生要掌握软件需求分析的基本概念。

需求是多层次的，包括业务需求、用户需求和系统需求，这三个不同层次从目标到具体，从整体到局部，从概念到细节。

（1）业务需求。业务需求是指反映企业或客户对系统高层次的目标要求，通常来自项目投资人、购买产品的客户、客户单位的管理人员、市场营销部门或产品策划部门等。
通过业务需求可以确定项目视图和范围，项目视图和范围文档把业务需求集中在一个简单、紧凑的文档中，该文档为以后的开发工作奠定了基础。

（2）用户需求。用户需求描述的是用户的具体目标，或用户要求系统必须能完成的任务。
也就是说，用户需求描述了用户能使用系统来做些什么。通常采取用户访谈和问卷调查等方式，对用户使用的场景（scenarios）进行整理，从而建立用户需求。

（3）系统需求。系统需求是从系统的角度来说明软件的需求，包括 功能需求、非功能需求 和 设计约束 等。
功能需求也称为行为需求，它规定了开发人员必须在系统中实现的软件功能，用户利用这些功能来完成任务，满足业务需要。
功能需求通常是通过系统特性的描述表现出来的，所谓特性，是指一组逻辑上相关的功能需求，表示系统为用户提供某项功能（服务），使用户的业务目标得以满足；
非功能需求是指系统必须具备的属性或品质，又可细分为软件质量属性（例如，性能（Performance）、安全性（Security）、可用性（Availability）、可修改性（Modifiability）等）和其他非功能需求。

质量功能部署（Quality Function Deployment，QFD）是一种将用户要求转化成软件需求的技术，其目的是最大限度地提升软件工程过程中用户的满意度。
为了达到这个目标，QFD 将软件需求分为三类，分别是常规需求、期望需求和意外需求。

（1）常规需求。用户认为系统应该做到的功能或性能，实现越多用户会越满意。

（2）期望需求。用户想当然认为系统应具备的功能或性能，但并不能正确描述自己想要得到的这些功能或性能需求。
如果期望需求没有得到实现，会让用户感到不满意。

（3）意外需求。意外需求也称为兴奋需求，是用户要求范围外的功能或性能（但通常是软件开发人员很乐意赋予系统的技术特性），实现这些需求用户会更高兴，但不实现也不影响其购买的决策。意外需求是控制在开发人员手中的，开发人员可以选择实现更多的意外需求，以便得到高满意、高忠诚度的用户，也可以（出于成本或项目周期的考虑）选择不实现任何意外需求。

==== 记住考试套路
* 安全、性能、可靠性、易用性 → 非功能需求
* 必须用某数据库、某平台、某语言 → 设计约束
* 用户具体怎么操作、录入什么 → 用户需求
* 用户“认为一般应该”怎样 → 期望需求

==== 答案解析
这道题考查的是设计模式的分类和特点。我们逐空分析：

'''''

*（1）结构型*

设计模式按目的分为三大类：

* *创建型*（Creational）：关注对象的创建
* *结构型*（Structural）：关注类和对象的组合
* *行为型*（Behavioral）：关注对象之间的交互和职责分配

所以（1）填 *结构型*，对应选项 *C*。

'''''

*（2）Singleton（单例模式）*

创建型模式包括：Singleton（单例）、Factory Method（工厂方法）、Abstract Factory（抽象工厂）、Builder（建造者）、Prototype（原型）。

选项中：

* Adaptor（适配器）→ 结构型
* Facade（外观）→ 结构型
* Command（命令）→ 行为型
* *Singleton（单例）→ 创建型* ✔

所以（2）选 *D*。

'''''

*（3）Memento（备忘录模式）*

行为型模式包括：Observer、Strategy、Command、State、Chain of Responsibility、Interpreter、Iterator、Mediator、Memento、Template Method、Visitor 等。

选项中：

* Decorator（装饰器）→ 结构型
* Composite（组合）→ 结构型
* *Memento（备忘录）→ 行为型* ✔
* Builder（建造者）→ 创建型

所以（3）选 *C*。

'''''

*（4）Bridge（桥接模式）*

题干描述："`将一个复杂的组件分成功能性抽象和内部实现两个独立的但又相关的继承层次结构，从而实现接口与实现分离。`"

这正是 *Bridge（桥接）模式* 的定义——将抽象部分与它的实现部分分离，使它们都可以独立地变化。

* *Bridge（桥接）→ 结构型* ✔（正确答案）
* Prototype → 创建型
* Flyweight → 结构型（但用于共享对象，不是接口与实现分离）
* Adapter → 结构型（用于接口转换，不是分离抽象与实现）

所以（4）选 *D*。

4.在海量数据和分析手段增多的情况下,数据展现则主要保障系统分析结果的可视化.

== 项目管理


=== 敏捷开发之 Scrum
在敏捷开发方法中，有固定的开发周期（Sprint），包含三个主要角色，并且每天进行站立会议（Daily Stand-up）的开发框架是（）。

- A 看板（Kanban）
- B 极限编程（Extreme Programming, XP）
- C 精益开发（Lean）
- #D Scrum#

---

本题考察的是敏捷开发方法的分类与核心特征。

敏捷开发（Agile Development）是一种强调迭代、增量、团队协作、快速反馈的软件开发方法。
常见的敏捷框架包括 Scrum、看板（Kanban）、极限编程（XP）、精益（Lean）等。
其中，Scrum 是当前最主流、应用最广泛的敏捷框架之一，这里做个补充，它具有以下显著特征：

1. 固定周期（Sprint）：每次迭代称为一个冲刺周期（Sprint），通常为 1～4 周。每个 Sprint 都应交付一个可用的、可测试的产品增量。

2. 三个角色（Three Roles）： 产品负责人（Product Owner）：负责定义产品目标与需求优先级。 Scrum 主管（Scrum Master）：保证 Scrum 流程顺利执行，移除障碍。 开发团队（Development Team）：跨职能团队，负责实现产品增量。

3. 每日站会（Daily Scrum）：每天进行约 15 分钟的站立会议，讨论： 昨天做了什么？今天准备做什么？是否遇到阻碍？

4. 其他关键活动： Sprint 计划会（Sprint Planning）、 Sprint 评审会（Sprint Review）、Sprint 回顾会（Sprint Retrospective）

- A 选项 看板（Kanban）：没有固定迭代周期，以持续流（Continuous Flow）方式工作。
- B 选项 极限编程（XP）：强调工程实践，如结对编程、持续集成、测试驱动开发等，但没有固定角色划分与每日站会要求。
- C 选项 精益开发（Lean）：关注减少浪费与流程优化，不强调固定周期或角色划分。
- D 选项 Scrum：符合题干描述——固定周期、三角色、每日站会。

因此，正确答案为 D（Scrum）

=== 进度管理
某项目包含任务 A、B、C、D、E、F，其持续时间及前序关系如下：

* A 需要 4 天，无前序；
* B 需要 3 天，前序为 A；
* C 需要 5 天，前序为 B；
* D 需要 3 天，前序为 C 和 E；
* E 需要 4 天，前序为 A；
* F 需要 1 天，前序为 D。

项目从第 1 天早上开始。请问任务 E 最晚可以在第几天早上开始？C 9

* A 5
* B 8
* #C 9#
* D 10

==== 答题解析
这道题可以拆解成一个**“画时间轴”**的简单方法。

[discrete]
==== 第一步：正向推算（找最长的那条路）

我们从左往右推，看看每个任务最早什么时候能做完。*（注意：遇到有多个前序任务时，必须等最晚的那个做完才能开始）*

[arabic]
. *A（4天）*：第1天开始，第4天结束。画一条线 `1----4`。
. *B（3天）*：等A做完，第5天开始，第7天结束。画线 `5---7`。
. *C（5天）*：等B做完，第8天开始，第12天结束。画线 `8-----12`。
. *E（4天）*：*E的前序也是A*。所以A在第4天做完，E就可以在第5天开始，第8天结束。画线 `5----8`。
. *D（3天）*：*D的前序是C和E*。必须等C和E**都**做完。C在第12天做完，E在第8天做完。既然要等两个，那就得等最晚的那个（C）。所以D只能从第13天开始，第15天结束。画线 `13--15`。
. *F（1天）*：等D做完，第16天开始，第16天结束。

*到这里，总工期算出来了，是16天。* 最关键的那条路是 A -++>++ B -++>++ C -++>++ D -++>++ F（一步都不能拖）。

[discrete]
==== 第二步：反向推算（找E的最晚底线）

现在我们从右往左推，看看任务E最晚能拖到什么时候，还不至于让整个项目延期（必须保证在第16天完成）。

[arabic]
. *F* 必须在第16天结束。
. *D* 必须在第15天结束（因为F要做1天）。
. *D 需要做3天*，所以D最晚必须在**第13天**开始（13, 14, 15）。
. 现在看 *E*：E做完之后，D才能开始。既然D最晚第13天早上必须开工，那么*E最晚必须在第12天结束*。
. *E 需要做4天*。如果第12天结束，往前数4天（12、11、10、9），*E最晚必须在第9天开始*。

*所以答案就是：第9天。*

*考试技巧总结：* 看到这种题，*不要纯在脑子里想*。在草稿纸上把任务顺着排一下，遇到分叉就并排画，遇到汇合就选时间长的那个。算出总工期后，倒着往回减，一分钟就能出结果。这道题在系统架构设计师的选择题里经常出现，属于必须拿分的“送分题”。

=== 工程费用计算

以此最低费用完成该工程需要（2）天。

|===

|A|---|3|10|1|4
|B|A  |7|15|3|2
|C|A  |4|12|2|4

* #A 106#   B 108   C 109   D 115

==== 费用是如何计算的？
*直接费用*：为完成具体作业直接花掉的钱，比如人工费、材料费、机械使用费等。

* 题表中“正常进度共需直接费用”就是各作业按正常天数完成时的直接费用；例如 A 正常 3 天需 10 万元。 +
“赶工进度下每天需增加的直接费用”是指：如果把这个作业压缩一天，需要额外多花的直接费。例如 A 每压缩 1 天，多花 4 万元。 但是 A 活的基础费用 10 万元是省不掉的。

*间接费用*：不是某个具体作业直接消耗的费用，而是整个工程期间每天都会发生的费用，比如管理费、场地费、监理费、临时设施费、贷款利息等。

* 本题间接费用为 *每天 5 万元*，所以若工程工期为 stem:[T] 天，则：

[stem]
++++
\text{间接费用}=5T\text{ 万元}
++++

总费用为：

[stem]
++++
\text{总费用}=\text{直接费用}+\text{间接费用}
++++

正常进度下，各作业直接费用合计：

[stem]
++++
10+15+12+18=55\text{ 万元}
++++

正常工期由关键路径决定：A—C—D 为：

[stem]
++++
3+4+5=12\text{ 天}
++++

所以正常总费用为：

[stem]
++++
55+5\times12=115\text{ 万元}
++++

赶工时，压缩工期会增加直接费用，但会减少间接费用。判断是否值得压缩，就是看“压缩一天增加的直接费”是否小于“节省的间接费 5 万元/天”。

本题通过压缩关键路径上的作业，可使总费用最低为：

[stem]
++++
106\text{ 万元}
++++

对应工期为：

[stem]
++++
7\text{ 天}
++++

所以答案是：

[arabic]
. *A：106 万元*
. *A：7 天*

具体分析参考下面内容。

==== 赶工进度最少天数
以 A 作业为例：

* 正常进度：需要 *3 天*
* 赶工进度：最少天数 *1 天*
* 赶工每天需增加直接费用：*4 万元/天*

意思是：

* A 正常做要 3 天；
* 如果赶工，最多可以压缩到 **1 天**完成；
* 从 3 天压到 1 天，一共压缩了 stem:[3-1=2] 天；
* 每压缩 1 天，多花 4 万元；
* 若把 A 压到最少 1 天，则额外增加直接费用 stem:[2\times4=8] 万元。

所以“赶工进度下所需的最少天数”表示的是**该作业允许的最短完成时间是几天**。

再比如 B：

* 正常 7 天；
* 赶工最少 3 天；
* 每天增加直接费用 2 万元。

表示 B 可以从 7 天压缩到 3 天，最多压缩 stem:[7-3=4] 天；每压缩 1 天多花 2 万元。

==== 最终分析
答案： +
（1）A，106 万元； +
（2）A，7 天。

* A→B：3＋7＝10 天；
* A→C→D：3＋4＋5＝12 天。

[stem]

++++

[stem]

++++

====== 2. 压缩公共作业 A
此时两条线路 A→B 和 A→C→D 均为关键线路。A 是两条线路的公共作业，压缩 A 可以同时缩短两条线路。

A 每天增加直接费 4 万元，小于间接费 5 万元，因此合算。

A 可以从 3 天压缩到 1 天，共压缩 2 天：

费用变化：

[stem]
++++
\text{增加直接费}=2\times4=8
++++

[stem]
++++
\text{节约间接费}=2\times5=10
++++

总费用减少：

[stem]
++++
10-8=2
++++

总费用变为：

[stem]
++++
109-2=107\text{ 万元}
++++

此时：

* A→B：stem:[1+7=8] 天；
* A→C→D：stem:[1+4+3=8] 天。

总工期为 8 天。

====== 3. 同时压缩 B 和 D
此时两条线路均为关键线路，要继续缩短总工期，必须同时压缩两条线路上的作业。

可选择：

* 压缩 B：每天增加 2 万元；
* 压缩 D：每天增加 2 万元。

合计每天增加：

[stem]
++++
2+2=4\text{ 万元}
++++

小于每天节约的间接费 5 万元，因此合算。

将 B 从 7 天压缩到 6 天，D 从 3 天压缩到 2 天，各压缩 1 天：

费用变化：

[stem]
++++
\text{增加直接费}=2+2=4
++++

[stem]
++++
\text{节约间接费}=5
++++

总费用减少：

[stem]
++++
5-4=1
++++

总费用变为：

[stem]
++++
107-1=106\text{ 万元}
++++

此时：

* A→B：stem:[1+6=7] 天；
* A→C→D：stem:[1+4+2=7] 天。

总工期为 7 天。

====== 4. 是否还能继续压缩？
此时 A 已达到最少 1 天，D 已达到最少 2 天。

若想继续把工期从 7 天压缩到 6 天，需要同时压缩 B 和 C：

[stem]
++++
\text{B 增加 }2\text{ 万元/天，C 增加 }4\text{ 万元/天}
++++

合计：

[stem]
++++
2+4=6\text{ 万元/天}
++++

而压缩一天只能节约间接费 5 万元，因此会亏：

[stem]
++++
6-5=1\text{ 万元}
++++

所以继续压缩不经济。

===== 四、最终结果
最终各作业工期为：

[stem]
++++
A=1,\quad B=6,\quad C=4,\quad D=2
++++

总工期：

[stem]
++++
\max(1+6,\;1+4+2)=7\text{ 天}
++++

最终直接费用：

[stem]
++++
\begin{aligned}
A &: 10+(3-1)\times4=18\\
B &: 15+(7-6)\times2=17\\
C &: 12\\
D &: 18+(5-2)\times2=24
\end{aligned}
++++

直接费合计：

[stem]
++++
18+17+12+24=71\text{ 万元}
++++

间接费：

[stem]
++++
7\times5=35\text{ 万元}
++++

总费用：

[stem]
++++
71+35=106\text{ 万元}
++++

因此：

[stem]
++++
\boxed{(1)\text{ A，}106\text{ 万元}}
++++

[stem]
++++
\boxed{(2)\text{ A，}7\text{ 天}}

=== Multi-agent systems
Multi-agent systems can operate under various （1）.

In centralized networks, a central unit contains the global knowledge base, connects the agents and oversees their information. 

A strength of this structure is the ease of communication between agents and （2） knowledge. 

A weakness of the centrality is the dependence on the central unit; if it fails, the（3） system of agents fails. 

Agents in decentralized networks share information with their（4）agents instead of a global knowledge base. Some benefits of decentralized networks are robustness and modularity. 

The failure of one agent does not cause the overall system to fail since there is no central unit.
